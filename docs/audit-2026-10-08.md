# Audit of MDtemplate v1.1.0 — 2026-10-08

Scope: every file in this repo (45 files), checked against the goal stated for v2
("a wizard that builds a top-grade personal Claude Code harness for any user, knows
the best skills and plugins, reads how the user prompts, and ends with a designed
HTML diagram of the result") and against the current Claude Code surface
(v2.1.294, verified 2026-10-08 — see `research-2026-10-08.md`).

## Verdict

v1.1.0 is a correct, carefully maintained **2025-shape developer wizard**. Its July
2026 correctness pass was real work: hooks read stdin, provenance-aware reset,
no fabricated MCP packages. But it is not the product in the goal, and the
distance is structural, not cosmetic:

| Goal | v1.1.0 |
|---|---|
| Any user, any life task | Developers only (7 coding roles) |
| Free-form interview, adaptive loops | Three fixed question rounds |
| Reads the user's prompting style, compensates for it | Absent |
| Knows the best skills and plugins (the core value) | 4 hand-written skills, 4 agents, no ecosystem knowledge |
| Baseline document / PDF / OCR skills | Absent |
| Generated harness at the current standard | 120-line CLAUDE.md, inline `node -e` hooks, implementer agents, no memory, no packaging |
| Designed HTML architecture diagram | Text cheat sheet |
| 300k-star repo quality | No README, no LICENSE, no git, no CI, no sample output |

Recommendation: **rebuild as v2.0.0**, keeping the four things v1.1.0 got right
(below). The audit findings are ordered by how much they block the goal.

## Keep (this is good)

1. **Provenance-aware safety** — `created` vs `merged` modes, timestamped backups
   before any write, reset that refuses to delete merged files
   ([prepare-workspace/SKILL.md:75-83](../.claude/skills/prepare-workspace/SKILL.md#L75-L83),
   [reset-setup/SKILL.md:41-51](../.claude/skills/reset-setup/SKILL.md#L41-L51)).
2. **Resume state** with version drift detection (`.wizard-state.json`, `VERSION`).
3. **Accuracy discipline** — the 1.1.0 changelog removed fabricated packages and
   non-existent env vars. v2 must keep that habit (dated, cited claims).
4. **The "show before write, confirm, never overwrite silently" rules** in
   `CLAUDE.md`.

## Findings

### A. Audience and interview (blocks the goal)

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| A1 | Only coders can use it. Roles, presets, skills, agents, hooks, project variants all assume a developer. | [settings-presets.md](../templates/settings-presets.md) (7 dev roles), Phase 4 and 6 of the wizard | The goal is "whatever the user does in life". Research: non-developers are served by almost no competitor; Anthropic's `knowledge-work-plugins` (legal, marketing, sales, finance, PM, support) plus the document skills fill the gap. |
| A2 | Interview is a fixed script: three rounds, then a profile. No loop, no coverage tracking, no "show me a real task" probe. | [SKILL.md:107-138](../.claude/skills/prepare-workspace/SKILL.md#L107-L138) | The goal asks for free expression with Claude adapting. A fixed script cannot discover a lawyer's or a video creator's workflow. |
| A3 | No prompting-style analysis. The wizard never looks at *how* the user writes. | whole skill | The goal asks for strengths/weaknesses extraction and an architecture that compensates. Anthropic's AI Fluency Index gives a measured 11-behavior rubric with base rates; `/insights`, `/doctor prompt-audit` and the `discernment-nudge` skill are prior art. |
| A4 | Language handling is "switch after Round 3". | [SKILL.md:111-112](../.claude/skills/prepare-workspace/SKILL.md#L111-L112) | Fine as far as it goes. v2 should detect language from the first message and set the `language` setting in the generated config. |

### B. Ecosystem knowledge (blocks the goal)

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| B1 | The catalog is four generic skills and four generic agents. Nothing from the official plugin marketplace, `anthropics/skills`, superpowers, mattpocock's skills, the `skills` CLI, or any ranked source. | [templates/skills/](../templates/skills/), [templates/agents/](../templates/agents/) | "It takes experience to know which skills are effective" is the problem v2 solves. There is no knowledge to encode yet. |
| B2 | No live discovery. If a user's need is not in the templates, the wizard has nothing. | Phase 4 | The `skills` CLI exposes a public search API (`skills.sh/api/search`) and `find-skills` is the #1 installed skill. v2 needs a curated catalog first and live search as fallback. |
| B3 | No trust model. Nothing ranks by install counts, verified badges, token cost, audit verdicts, or license. | — | Research: stars and skills.sh installs are gamed (a trojan family reached 1.7M installs). Anthropic's document skills are proprietary and must be installed from the marketplace, never bundled. |
| B4 | No document / PDF / OCR baseline. | — | Explicit goal. Pending research will set the chain (text layer → markitdown/docling → OCR → vision). |
| B5 | Install channels are not inventoried. The wizard copies files without checking `enabledPlugins`, `~/.claude/skills`, `~/.agents/skills`, or `.skill-lock.json`. | Phase 4 | Duplicate installs (plugin + skills CLI) are a known failure mode; a wizard that adds a second copy makes the harness worse. |

### C. Quality of the generated harness

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| C1 | Global CLAUDE.md target is "under 120 lines" and mixes identity, coding standards, workflow and security boilerplate. | [global-claude-md.md:10-44](../templates/global-claude-md.md#L10-L44) | Official guidance: under 200 lines, only what Claude cannot derive, "would removing this cause mistakes?". ETH Zurich (2026): context files add over 20% cost and do not generally raise success. Chiron keeps the always-loaded layer near 60 lines. Coding standards belong to linters and path-scoped rules; "never commit secrets" belongs to deny rules and hooks. |
| C2 | No memory system. Auto memory (`~/.claude/projects/<p>/memory/`, `MEMORY.md`, four memory types) is never explained or seeded. | Phase 2 | This is how the harness "knows the user" across sessions. |
| C3 | Agents are implementers (`test-writer`, `doc-writer` write files) with pinned `model: sonnet`. | [templates/agents/*.md](../templates/agents/) line 5 | Current practice (Anthropic harness-design post, Chiron Law 5): subagents for isolation — reviewer, verifier, researcher — never for writing. Pinning a cheaper model into a reviewer silently degrades judgment; `inherit` or explicit tiering is the pattern. Agents also now have 18 frontmatter fields including `memory`, `permissionMode`, `effort`. |
| C4 | Skill descriptions say what the skill does, not when to use it. | [smart-commit/SKILL.md:3](../templates/skills/smart-commit/SKILL.md#L3) etc. | superpowers' tested finding: descriptions that summarize workflow make agents skip the body. "Use when…" trigger style; `when_to_use` field now exists. |
| C5 | No packaging. Files are scattered across `~/.claude/{agents,skills}` and `settings.json` with no single source of truth. | Phase 4-5 | Claude Code now supports "skills-dir plugins": one folder under `~/.claude/skills/<name>/` with `.claude-plugin/plugin.json` loads every session as `<name>@skills-dir` and can be disabled with one command. Chiron's architecture doc rejected loose files for exactly this reason. |
| C6 | Project template is a copy-this-folder convention. | Phase 6 | `/init` (now interactive with `CLAUDE_CODE_NEW_INIT=1`) and `/import` exist; v2 should generate a `/new-project` skill that drives them, not a folder to copy. |
| C7 | Permissions are the centre of the generated settings. | [settings-presets.md](../templates/settings-presets.md) | Auto mode is the built-in starting mode since v2.1.283. Allow lists matter less; deny rules for secrets, `ask` for egress verbs, and `Edit()` denies matter more. `Glob`/`Grep` are absent by default on macOS/Linux/WSL. |

### D. Hooks implementation

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| D1 | Every functional hook is a `node -e` one-liner embedded in JSON. | [auto-format-web.md:26](../templates/hooks/auto-format-web.md#L26), [safety-guard.md:30](../templates/hooks/safety-guard.md#L30) | Fragile quoting; unreviewable; blocked by common security policies (this machine's own settings deny `Bash(node -e *)`). Official pattern: script files under `.claude/hooks/` or `~/.claude/hooks/`, invoked in exec form (`"command": "node", "args": [...]`) which bypasses the shell entirely. |
| D2 | Only 3 hook ideas (safety, format, notify). | [hooks-catalog.md](../templates/hooks/hooks-catalog.md) | 33 events and 5 handler types exist, including `prompt` and `agent` hooks (an LLM-judged Stop gate: "did you verify?"). Missing: secrets guard that covers Bash workarounds, backup-outside-git, context guard, post-compaction re-injection, session-start context, and a prompt-coaching hook tied to the prompting profile. |
| D3 | `Notification` hooks use `matcher: ""`. | [notify.md](../templates/hooks/notify.md) | Still valid, but matchers now exist (`permission_prompt`, `idle_prompt`, `agent_needs_input`…) and `terminalSequence` gives OSC desktop notifications without a shell command. |

## Priority

1. **B + A** (catalog, interview, prompting profile) — this is the product.
2. **C + D** (generated harness shape, hooks) — this is the quality bar.
3. **G** (HTML deliverable) — this is the visible result.
4. **F** (verification, day-2 loop) — this is what makes it trustworthy.
5. **H + I + E** (repo hygiene, guides, settings) — this is what makes it shareable.

The design that addresses these is in the v2 spec (to be written after approval).
